# MAUI DevFlow website

## Register

brand

## Platform

web

## Users

.NET MAUI developers who use AI coding agents and need those agents to work beyond source code. They are building and debugging native apps on simulators and devices, often inside an iterative build-run-inspect-fix loop.

## Product Purpose

Explain, in seconds, that MAUI DevFlow gives AI coding agents live eyes, hands, and diagnostics inside a running native app. The site should move a visitor from immediate understanding to confidence, then into the shortest credible setup path.

## Positioning

MAUI DevFlow closes the loop between AI-generated code and the real app by letting agents see, operate, inspect, and verify native MAUI experiences.

## Conversion & proof

- Primary CTA: follow the setup instructions and get DevFlow running.
- Secondary CTA: inspect the complete capability surface and source repository.
- The line a visitor remembers after 10 seconds: Your agent can write the app. Now it can use it, too.
- Belief ladder: AI coding stops too early; DevFlow connects to the running app; it operates real native views; it exposes the diagnostics needed to verify and fix; setup is short and project-scoped.
- Proof on hand: the shipped CLI, MCP server, in-app agent, cross-platform driver, and 69 structured tools documented in this repository.

## Brand Personality

Confident, clear, and alive. The voice is direct and technically literate without sounding like documentation. It should make a powerful developer tool feel immediately approachable rather than severe or terminal-led.

## Anti-references

Do not copy ailoha.dev, its colors, or its composition. Its device-led storytelling is useful inspiration, but DevFlow should own a distinct .NET MAUI purple identity. Avoid generic neon AI gradients, faux testimonials, fake metrics, repeated icon-card grids, and terminal cosplay that does not demonstrate real DevFlow behavior.

## Design Principles

1. Lead with the closed loop, not the feature list.
2. Demonstrate the product through credible live tool sequences.
3. Make native reach explicit: real views, simulators, and devices.
4. Keep every claim traceable to a shipped DevFlow capability.
5. Turn interest into action with a setup path that reads in under a minute.

## Accessibility & Inclusion

Maintain strong contrast, complete keyboard access, visible focus, semantic landmarks, readable type at zoom, and a reduced-motion mode. Motion must clarify cause and effect rather than gate content.
