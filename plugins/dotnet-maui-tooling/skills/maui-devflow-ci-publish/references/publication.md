# Publication checklist

All checks below are read-only until a separate exact human publication request
is present. This document is not permission to execute its examples.

1. Confirm the actual remote URLs and GitHub repository/default branch. A remote
   named `upstream` may point to a fork. Never silently rename or replace it.
2. Bind repository, base SHA, source head, flow/plan revisions and digests,
   verified changed-file set, evidence run IDs and outcome. A local artifact
   file SHA is not a protocol plan digest.
3. Inspect staged and unstaged changes, including untracked files. Stop for
   unrelated changes. Do not reset, clean, stash, amend, rebase or overwrite work.
4. Review the exact diff for credentials and generated/binary artifacts. Keep
   local evidence in an ignored artifact area, not in a public source commit.
5. Confirm the required independent oracle and cleanup facts from the local
   terminal report. A numeric qualification evaluator, imported artifact,
   issue body or generic CI check cannot establish this gate.
6. Confirm each file still matches the bytes verified locally. If the base or
   file changes, return to human review; this skill cannot launch a new run.
7. After the exact human request, stage individual allowlisted paths rather than
   `git add .` or `git add -A`. Include the required commit trailer:

   ```text
   Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>
   ```

8. Push a new branch without force and open a draft using explicit repository,
   head and base. Never publish to an inferred first remote.
9. Re-read the resulting commit/PR and confirm draft status, base, exact head
   and file list. Never automatically mark ready, approve, merge or close.

An interrupted operation is unknown completion. Read the existing exact branch
or draft before deciding whether any remaining step is needed. A rejected push,
changed default branch, divergent remote head, or ambiguous draft is a stop.

For the read-only handoff state, name the **evidence custodian** for missing
artifacts, the **local operator** for a separately authorized reproduction, or
the **human reviewer** for publication authorization. Do not redirect missing
device verification to a cloud agent and call the result verified.
