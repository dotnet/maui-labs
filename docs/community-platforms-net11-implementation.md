# Community platform .NET 11 implementation and validation

This report maps the approved modernization work packages to the implementation
in this branch. It deliberately separates source/compile evidence from native
runtime evidence. The release contract is not considered native-certified until
the Linux, Windows, and Xcode 27 CI lanes execute successfully.

## Native feature disposition

| Backend/capability | Status | Exact behavior or blocker |
|---|---|---|
| GTK secure storage | Implemented, native validation pending | Uses libsecret's `secret-tool`, sends values only through standard input, and scopes entries by application and encoded key. Redirected lookup output is returned byte-for-byte as text, including trailing LF/CRLF. Exit 1 means no match only when stderr is empty; diagnostics propagate. Values above 8191 UTF-8 bytes are rejected before `secret-tool` can truncate them. The sync facade uses a context-independent async chain, and the bounded single-thread synchronization-context regression passes. There is no plaintext fallback. |
| GTK process-scoped fonts | Implemented, native validation pending | Uses `FcConfigAppFontAddFile` and notifies the Pango font map. It no longer copies fonts into the user's persistent font directory. Same-name/different-content rendering and read-only-home execution still require Linux. |
| GTK accessibility | Implemented, native validation pending | Semantic announcements use `Gtk.Accessible.Announce`; CollectionView exposes native list/list-item roles. Description, Hint, and Heading use GirCore's generated typed `GObject.Value[]` bridge to the internal `Gtk.Internal.Accessible.UpdateProperty` binding, avoiding an ABI-unsafe direct varargs P/Invoke. The pinned GirCore contract is asserted in tests. AT-SPI output and virtualized focus remain Linux runtime tests. |
| GTK one-shot location | Implemented, native validation pending | Requires GeoClue's `where-am-i`; parses the real degree-suffixed invariant output, forces the child locale to `C`, returns as soon as the first complete fix is emitted instead of waiting for the utility's 30-second lifetime, and honors request timeout/cancellation. Missing utility, permission diagnostics, process failure, and incomplete results are explicit. |
| GTK continuous location | Implemented, native validation pending | A cancellable listener repeatedly queries GeoClue's `where-am-i`, honors `MinimumTime` and `MinimumDistance`, caches the last result, rejects duplicate starts, and raises `LocationChanged` or `ListeningFailed`. Cancellation and disposal are serialized by a single session owner, so Stop cannot race a disposed token source. Location/failure publication is session-gated, preventing provider completion from emitting stale events after Stop returns. Deterministic cancel/dispose and deferred-provider regressions pass on both TFMs. This is explicitly polling, not a long-lived GeoClue D-Bus subscription. |
| GTK camera capture | Implemented for V4L2, native device validation pending | Uses `gst-launch-1.0` without a shell and requires an actual `/dev/video*` device plus the `v4l2src`, `videoconvert`, `jpegenc`, `vp8enc`, and `webmmux` plugins. It does not use `autovideosrc`, which can substitute `videotestsrc` and return synthetic media when no camera exists. Photos produce JPEG; video produces VP8/WebM. Cancel/Stop, timeout, failure, and partial-file cleanup are explicit. Portal-only cameras without a V4L2 device remain unsupported. CI validates codecs/containers deterministically and uses `v4l2src` only when `/dev/video0` exists. |
| WPF media picker | Selection implemented; capture unsupported | Uses `OpenFileDialog` for image/video selection. Camera capture reports `IsCaptureSupported=false` and throws `FeatureNotSupportedException`; the backend no longer calls the UWP-only `Windows.Media.Capture.CameraCaptureUI`. A supported implementation requires adding and validating the Windows App SDK desktop `Microsoft.Windows.Media.Capture.CameraCaptureUI` dependency/bootstrap path on Windows. |
| WPF battery/power | Implemented, native validation pending | Uses `GetSystemPowerStatus`, reports absent/charging/full/discharging states, AC/battery source, battery saver, and change events through polling. Native percentage/flag value 255 maps to unknown rather than synthetic full charge; no battery reports charge -1. Timer read failures are caught and published instead of escaping the callback. |
| WPF semantic announcements | Implemented, native validation pending | Maintains a live-region `TextBlock` in the active WPF window and raises `LiveRegionChanged` through UI Automation. |
| WPF text to speech | Implemented, native validation pending | Uses built-in Windows SAPI voices, locale enumeration, volume/rate/voice selection, and cancellation. MAUI 11 `Locale` is constructed directly with language/country/name/id; the net10 compatibility path requires the verified constructor and fails explicitly instead of creating uninitialized objects. Stable voice ID has exact priority; when it is absent, selection matches language plus optional country, with name used only when neither ID nor language is supplied. Null/empty text and out-of-contract volume/rate/pitch now fail instead of succeeding or clamping. SAPI pitch is explicitly unsupported rather than silently ignored. Missing SAPI is explicit. |
| WPF app actions | Implemented for packaged apps, native validation pending | Uses `Windows.UI.StartScreen.JumpList`, persists action IDs/titles as escaped arguments, tokenizes the complete activation string, and holds a pending activation until actions and a subscriber are available. Round-trip coverage includes spaces, percent characters, and Unicode. `IsSupported` remains false for unpackaged apps without Jump List support. Cross-process single-instance forwarding is not added; Windows may launch a new app process for the action. |
| WPF camera capture | Explicitly unsupported | `Windows.Media.Capture.CameraCaptureUI` is UWP-only and has been removed from the backend. The supported Windows App SDK desktop API is not currently a package/bootstrap dependency, so claiming capture support would be success-shaped and unsafe. |
| WPF location | Implemented, native validation pending | Uses `Windows.Devices.Geolocation.Geolocator` for one-shot and foreground updates, requests permission, treats Disabled/NotAvailable as unavailable, maps NoData to a listener error, honors caller cancellation and `GeolocationRequest.Timeout`, movement/time thresholds, and caches the last location. Packaged/unpackaged permission behavior still requires Windows. |
| WPF sensors | Explicitly unsupported | The backend has no accelerometer, gyroscope, magnetometer, compass, or barometer provider and does not synthesize readings on desktop hardware. |
| WPF phone and SMS | Explicitly unsupported | Desktop Windows has no backend-owned telephony contract. Existing services report unsupported instead of fabricating successful phone or SMS actions. |
| AppKit photo capture | Implemented, native validation pending | Uses the native `IKPictureTaker`, requires an available AVFoundation video device, `NSCameraUsageDescription`, and granted AVFoundation camera permission; encodes the returned image as PNG in the cache directory and returns null only for user cancellation. The template carries camera privacy metadata. |
| AppKit video capture | Implemented, native validation pending | Uses an `AVCaptureSession`, `AVCaptureDeviceInput`, and `AVCaptureMovieFileOutput` for camera-only `.mov` recording. A native modal alert provides Stop and Cancel. Stop awaits `AVCaptureFileOutputRecordingDelegate.FinishedRecording` with a bounded timeout before returning a verified non-empty file. Cancellation, native failure, empty output, and timeout delete the partial cache file. It requests camera permission explicitly and does not capture audio or require microphone permission. A conditional self-hosted Xcode 27/camera CI gate is present because hosted macOS runners have no camera or pre-granted TCC identity. |

## Host boundaries

The implementation host is macOS with Xcode 26.4.1. Linux GTK/DBus/Secret
Service/display execution, Windows WPF/UI Automation/SAPI/power execution, and
AppKit .NET 11 execution under Xcode 27 were not available locally. Those are
real native validation requirements, not waived checks.
